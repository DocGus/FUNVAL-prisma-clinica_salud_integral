# Manual técnico de la plantilla Full Stack

## 1. Objetivo y alcance

La plantilla ofrece una API inicial con Node.js, TypeScript, Express,
PostgreSQL y Prisma ORM 7. Incluye validación de configuración, health check,
documentación OpenAPI básica, pruebas HTTP/unitarias y una prueba de conexión
PostgreSQL aislada.

No incluye frontend, autenticación, endpoints de dominio, modelos de negocio,
reglas de negocio ni migraciones de dominio. El proyecto derivado debe definir
esos elementos según sus requisitos.

## 2. Requisitos previos

- Node.js `>=20.19.0`.
- pnpm `12.18.0`, fijado por `packageManager`.
- PostgreSQL y una base disponible para ejecutar la prueba de integración.
- Una base normal configurada en `DATABASE_URL` cuando se ejecute la
  aplicación conectada a PostgreSQL.

La prueba de integración requiere, además, una base PostgreSQL **exclusiva para
pruebas**, configurada mediante `TEST_DATABASE_URL`. Su nombre debe terminar
en `_test`.

## 3. Instalación e inicio

Desde la raíz del proyecto:

```sh
pnpm install
cp .env.example .env
```

Configura las URLs en `.env`; nunca publiques ese archivo ni compartas sus
credenciales. Genera el cliente Prisma e inicia la API:

```sh
pnpm prisma:generate
pnpm dev
```

La API escucha en `PORT` (por defecto `3000`), ofrece `GET /health` y publica
Swagger UI en `/api/docs`.

## 4. Stack y dependencias

Las versiones instaladas del entorno de desarrollo están fijadas por
`pnpm-lock.yaml`; los rangos del manifiesto se expresan en `package.json`.

| Componente | Uso |
|---|---|
| Node.js y pnpm | Runtime y gestión de paquetes |
| TypeScript | Tipado y compilación ESM con NodeNext |
| Express 5 | Aplicación HTTP, middleware y health check |
| Prisma ORM 7 | Esquema y cliente de acceso a datos |
| `@prisma/adapter-pg` y `pg` | Conexión PostgreSQL |
| Zod y dotenv | Validación y carga de entorno |
| Vitest y Supertest | Pruebas unitarias y HTTP |
| Swagger UI | Documentación OpenAPI básica |

JWT y bcryptjs no están incluidos porque no hay autenticación implementada.

## 5. Estructura del proyecto

```text
.
├── docs/                       Manuales y documentación
├── generated/                  Clientes Prisma generados (ignorado por Git)
├── prisma/
│   ├── migrations/             Sin migraciones de dominio iniciales
│   └── schema.prisma           Proveedor PostgreSQL y generador, sin modelos
├── src/
│   ├── config/
│   │   ├── env.schema.ts       Esquema Zod del entorno
│   │   ├── env.ts              Carga .env y valida el entorno
│   │   └── prisma.ts           Cliente Prisma normal de la aplicación
│   ├── app.ts                  Express, health check y Swagger UI
│   ├── server.ts               Inicio del servidor
│   └── controllers/            ┐
│       middlewares/            │ Directorios preparados para el proyecto
│       routes/                 │ derivado; contienen solo marcadores vacíos
│       schemas/                │
│       services/               │
│       utils/                  ┘
├── tests/
│   ├── integration/            Prueba de conexión PostgreSQL (SELECT 1)
│   ├── support/                Fábrica y validación de URL de prueba
│   └── *.test.ts               Pruebas HTTP, esquema y aislamiento
├── .env.example                Contrato de variables sin secretos
├── .gitignore                  Exclusión de entorno y artefactos generados
├── package.json                Dependencias y scripts
├── pnpm-lock.yaml              Resolución reproducible
├── prisma7.config.ts           Configuración de Prisma CLI de producción
├── tsconfig.json               Typecheck de src, tests y cliente de producción
└── tsconfig.build.json         Build limitado a producción
```

`dist/` es generado por el build y está excluido de Git. Las pruebas y su
configuración no se compilan en la salida de producción.

## 6. Flujo HTTP

```text
Cliente HTTP -> src/server.ts -> src/app.ts
                                  ├── CORS
                                  ├── parser JSON
                                  ├── GET /health -> {"status":"ok"}
                                  └── /api/docs -> Swagger UI
```

La aplicación y el servidor están separados para permitir pruebas HTTP con
Supertest sin iniciar el listener de producción. Aunque `src/config/prisma.ts`
exporta el cliente normal, los endpoints base aún no ejecutan consultas.

## 7. Prisma y conexiones

`prisma7.config.ts` carga el entorno, apunta a `prisma/schema.prisma` y a
`prisma/migrations`, y configura la URL de Prisma CLI desde `DATABASE_URL`.
`prisma/schema.prisma` declara PostgreSQL y genera el cliente en
`generated/prisma/`. `src/config/prisma.ts` crea `PrismaPg` con
`DATABASE_URL` y exporta la instancia normal de `PrismaClient`.

El esquema de producción inicia intencionalmente **sin modelos de negocio y sin
migraciones de dominio**. La carpeta de migraciones está preparada para el
proyecto derivado.

### Variables de entorno

| Variable | Propósito y validación |
|---|---|
| `DATABASE_URL` | Obligatoria para la aplicación; Zod exige URL válida. Prisma de producción utiliza esta conexión. |
| `TEST_DATABASE_URL` | Opcional fuera de integración. Solo la usa el cliente de prueba, exige URL PostgreSQL válida y nombre de base terminado exactamente en `_test`. |
| `PORT` | Puerto HTTP; entero positivo, por defecto `3000`. |
| `NODE_ENV` | `development`, `test` o `production`; por defecto `development`. |

`TEST_DATABASE_URL` debe apuntar a una base **exclusiva para pruebas**. El
cliente de integración no usa `DATABASE_URL` como alternativa. La prueba real
comprueba la conexión, ejecuta exclusivamente `SELECT 1 AS result` y
desconecta el cliente mediante `finally`; no migra ni modifica datos.

El cliente de integración vive bajo `tests/support/`, utiliza la misma salida
Prisma generada para la estructura de producción y no se importa desde `src/`.
Una prueba automatizada protege este límite.

## 8. Pruebas, typecheck y build

```sh
pnpm test
pnpm test:integration
pnpm typecheck
pnpm build
```

- `pnpm test`: pruebas unitarias, validación de entorno, límite de imports y
  HTTP con Supertest. No requiere conectar a PostgreSQL.
- `pnpm test:integration`: requiere `TEST_DATABASE_URL`; genera el cliente,
  ejecuta la prueba PostgreSQL con `SELECT 1 AS result` y desconecta. No aplica
  migraciones ni realiza escrituras.
- `pnpm typecheck`: genera el cliente Prisma normal y ejecuta `tsc --noEmit`,
  incluyendo las pruebas.
- `pnpm build`: genera el cliente normal y compila solo código de producción
  según `tsconfig.build.json`.

`pnpm prisma:generate` genera localmente el cliente de
`prisma/schema.prisma`. Los archivos bajo `generated/` son artefactos
regenerables y están excluidos de Git.

## 9. Archivos que debe adaptar un proyecto derivado

- `.env.example`: agregar los nombres y descripciones de nuevas variables, sin
  credenciales reales.
- `prisma/schema.prisma`: agregar los modelos propios del dominio. Crear,
  revisar y conservar migraciones conforme a la estrategia de ese proyecto.
- `src/app.ts` y `src/`: agregar routers, controladores, servicios, middleware,
  validación de solicitudes y reglas de negocio propias.
- `tests/`: añadir pruebas unitarias, HTTP y, si aplica, integración contra
  bases exclusivas de prueba.
- `README.md` y `docs/`: documentar configuración, comandos y decisiones
  específicas del proyecto derivado.

No agregues entidades ni reglas de negocio a la plantilla genérica. Mantén
`DATABASE_URL` y `TEST_DATABASE_URL` separadas, y no reutilices una base de
desarrollo o producción para pruebas de integración.

## 10. Scripts disponibles

| Comando | Función |
|---|---|
| `pnpm install` | Instala dependencias según el lockfile |
| `pnpm dev` | Genera el cliente Prisma normal e inicia Express con recarga |
| `pnpm prisma:generate` | Genera el Prisma Client de producción |
| `pnpm test` | Ejecuta pruebas unitarias y HTTP |
| `pnpm test:integration` | Comprueba PostgreSQL usando solo `TEST_DATABASE_URL` y `SELECT 1` |
| `pnpm typecheck` | Genera Prisma Client y verifica tipos de producción y pruebas |
| `pnpm build` | Genera Prisma Client y compila la salida de producción |
| `pnpm start` | Ejecuta `dist/src/server.js` tras un build |
| `pnpm exec prisma validate` | Valida el esquema Prisma normal |
